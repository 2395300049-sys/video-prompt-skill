# 选题、故事与口播

来源主线：S014、S016–S018、S037–S040、S045–S048、S056、S059–S062、S067–S074、S099、S103、S147、S152。编号可用检索脚本追溯。

## 把选题变成一句可证明的主张

先写“给谁看—解决什么问题—看完获得什么”。用人群 × 具体场景 × 困难组合选题，例如“刚租房的上班族 × 清晨出门 × 找不到钥匙”，比“生活小妙招”更容易形成画面。一次只讲一个主张，选题数量按需求决定。

有参考账号时，分别记录标题、封面、开场、内容结构、视听方式、评论问题和可见数据，再比较共性。高点赞不证明某个镜头或发布时间造成增长；没有后台数据时不写播放量、转化率或受众画像。

## 按内容选择结构

| 内容任务 | 结构 | 使用条件 |
| --- | --- | --- |
| 解释观点 | PREP：观点→理由→例子→回到观点 | 例子确实支持观点 |
| 操作教程 | 问题场景→步骤→可见结果→复核方法 | 步骤能拍出，结果可核对 |
| 常见错误 | 原做法→问题→改法→结果对比 | 比较条件相同，不编造效果 |
| 信息解读 | FIRE：事实→解释→反应/影响→收束 | 事实、判断、预测分清 |
| 产品说明 | 需求/风险→价值→差异→证据 | RIDE 是组织方式，不能替代功效证据 |
| 人物故事 | 愿望→阻碍→选择/行动→后果 | 动机与行动能连接 |
| 微电影 | 日常状态→异常→选择→变化→余韵 | 镜头数由时长决定，不固定五镜 |
| 情绪治愈 | 具体生活细节→感受变化→轻收束 | 不强行制造创伤或反转 |
| 书籍/影视解说 | 真实问题→作品中的具体内容→理解→回应问题 | 核对作者、情节、台词；遵守剧透要求 |
| 历史/新闻 | 已核实背景→事件→证据→意义或待解问题 | 传说、改编与事实分别标明 |

原资料中的“爆款”“黄金发布时间”是标题和策略表述，不是效果保证。若要选发布时间，先有实际账号历史数据，再设计可比较的试发记录。

## 开场与结尾

开场可以是明确结果、悬念、常见误区、具体动作或有依据的反差。开场提出的问题必须在正文兑现；避免正文不支持的绝对标题。陌生领域先交代必要背景，不为“前几秒钩子”牺牲理解。

结尾可以回扣开场、给一步可执行动作或提出与内容相关的问题。不要每条都添加关注、私信、下单等多个要求。文案里的 CTA 只是脚本内容，不是授权实际发布或发送。

## 长文改成口播

1. 列出不可改变的事实、数字、人物关系、作者观点和必要限定。
2. 删除重复铺垫，每段保留一个信息点；专业术语先用一句话解释。
3. 改成能顺畅说出的短句，合理分句，不硬套每句固定字数。
4. 将抽象判断转换成可观察的例子；资料没有的经历、采访、用户反馈不能补成真实事实。
5. 配置与信息同步的画面：讲步骤就拍步骤，讲对比就让对比条件可见。
6. 试读或用实际配音计时。仅作预估时可按每秒约 3–5 个汉字估算，停顿、数字、英文和情绪表演会改变速度；标注“待配音复核”。

需要 A/B 两版时，保持事实不变，只更换一个主要变量，例如开场角度或叙述顺序，并说明差异。没有必要时直接交付最合适的一版。

## 参考、改写与表达

从参考提炼节奏、信息层级、叙述视角、修辞和视听关系，再围绕当前对象重建内容。名人语录改写后不能仍署名为名人原话；地名、历史事实、产品参数不能为了降重而替换。S083 的城市文案可提炼“地理—文化—生活细节—个人情感”，不能把新写的句子归给原作者。

S031、S065、S085、S091 中涉及“去 AI”或检测的表述不构成本 skill 的目标。可采用具体细节、自然句式和真实声音；不加入假错字、假经历、伪造引用或检测保证。
